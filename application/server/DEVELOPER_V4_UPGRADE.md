# v1.7.0 开发者后台：接口、数据生效时机与部署边界

这次源代码新增开发者后台，但源代码提交、Windows EXE 发布不等于生产服务器升级。
生产升级必须另行获得批准，使用独立的迁移连接，先备份和验证；桌面端不能执行迁移、
获取数据库管理密码、SSH 命令或云厂商控制台权限。

## 接口与权限

- `POST /v1/developer/login`：输入已有管理者账号密码，验证 Argon2id 口令及独立
  `developer_grants` 授权，发放仅 15 分钟有效的二次验证能力。
  只有普通运营端登录令牌、只有用户名相同、只有 operator 身份，都不能进入开发者接口。
- `GET /v1/developer/users?role_code=operator|advisor|member`：三类账号分页。
- `GET /v1/developer/users/{id}`：账号及个人业务表；每表最多先返回 500 行。
  `truncated_tables` 告知分页需求；`GET .../records/{table}?offset=0&limit=100` 继续读取。
  口令哈希、令牌、加密密钥、服务器路径、原始二进制附件不返回。
- `PATCH /v1/developer/users/{id}`：修改账号名、重置口令、启停账号。
  密码只能重设，不能恢复或显示原密码；所有旧会话立即撤销，这是安全例外。
- `staff_account_terms` 顾问账号有效期属于同样的安全例外：修改立即生效并撤销旧会话，
  防止已经过期的顾问无法登录、无法启用延期。旧会话必须重新认证，修改留存审计记录。
- `PATCH /v1/developer/users/{id}/records/{table}/{row_id}`：只接受固定个人业务表和字段。
  使用数据库嵌套事务先验证约束并回滚，然后记录待生效修改。不能修改记录归属、主键、
  文件路径、审计日志或认证数据。
- `GET/PUT /v1/developer/settings`：读取/发布不可变的 AI、功能开关、应用级运行设置。
  PUT 需要 `expected_revision`；过期版本返回 409，避免覆盖其他人的工作。
  `api_key` 是独立的可选写入字段，永远不回显。
- `GET /v1/developer/server-status`（`/status` 为别名）：实际数据库连通检查、数据库类型、
  服务应用版本、UTC 时间、开发者结构和当前设置版本；不返回 DSN、IP 登录凭据或资源配置。
- `POST /v1/client-start`：普通已登录用户明确开始新的应用会话，启用自己的待生效修改，
  并捕获本次会话配置。`GET /v1/client-settings` 只读，不能触发业务修改。

## 延迟生效与冲突

除口令/账号启停/账号有效期等即时安全变更外，全局 AI/功能/应用运行设置在每次发布后创建新版本，旧版本不覆盖。
已打开应用持有原版本；下次打开或重新登录时重新捕获。没有新版客户端启动调用的旧客户端，
第一次 AI 请求会在服务器捕获当前配置。`X-Application-Settings-Revision` 仅用于验证：
客户端不能凭此指定旧版本、绕过功能关闭或偷用其他版本的密钥。

个人记录修改先进入 `developer_pending_changes`。目标用户下次明确启动时才写入业务表。
如果等待期间用户更新了原记录，指纹校验发现冲突，保留用户的新数据并标为 conflict；
不会悄悄覆盖。每次最多处理 100 条，超出部分下次启动继续。
修改共享关系（如顾问绑定）在目标启动后仍会正常参与已有业务同步；不提供整库历史快照隔离。

## 新增五张私有表

- `developer_grants`：由独立管理工具授权，运行角色只有 SELECT，不能自我授权。
- `developer_sessions`：与正常会话绑定的短期二次验证记录。
- `developer_settings_snapshots`：版本化配置、AES-256-GCM 密文及发布者/时间。
- `developer_pending_changes`：目标用户、记录、字段变更、原记录指纹、等待/生效/冲突状态。
- `developer_client_sessions`：服务器保存的令牌到已捕获配置版本映射。

全部启用并强制 RLS。新增的开发者和启动激活身份只能由已认证的服务器代码设置，
没有 HTTP 传入 SQL、数据库身份、任意脚本或无条件 BYPASSRLS；运行账号不会成为数据库管理员。
资料和配置编辑均记录审计元信息，不在审计中保存新口令、API Key 或完整个人隐私文本。

## AI 设置的实际边界

可配置模型（现有两种已支持名称）、复杂度、语气、输出长度（最高 2048）、补充提示词、
最多 20 项文本技能、50 条专业资料和 20 条每日提示。资料需 `reviewed=true` 才供客户端采用；
这些是固定程序读取的说明和资料，不是模型权重训练、完整向量知识库或自动执行代码插件。
技能触发词和资料关键词各最多 20 项，每项不超过 100 字符。总配置最多 256 KiB。
固定医疗安全约束不能由配置替换。桌面端负责按照捕获配置注入文字，代理端保留独立固定安全提示。

API Key 使用服务器挂载的 32 字节独立密钥文件加密。可以复用现有默认 AI 的专用加密密钥文件，
或通过 `HEALTHLIFE_DEVELOPER_KEY_FILE` 配置独立文件；不应放入源码、EXE、Git 或可公开下载的包。
未配置文件时拒绝保存 API Key，不会降级明文。普通用户只看到是否已配置，无需填写公共默认 Key。
私有默认密钥原本就只应在服务器使用，不可通过客户端获取。

应用级运行设置仅包括公告、联系说明、维护状态/说明、客户端超时（30—120 秒）。
会员的商品、AI、预约、记录写入和统计等固定接口会按已捕获的开关在后端再次检查，
不是只隐藏界面。关闭的离线记录上传返回明确的 `feature_disabled_*` 错误，不伪装成上传成功。
维护状态阻止普通业务调用，但保留登录、开发者恢复和新会话配置获取。
云服务器重启、SSH、数据库管理员、扩容、防火墙、证书和备份恢复仍是运维工作，未开放任意执行。

## 生产部署顺序（本次代码/本地测试不自动执行）

1. 独立 PostgreSQL 管理工具导出完整备份，包含平台全表与迁移版本；验证隔离恢复。
   v4 新增配置密文随库备份，独立加密密钥另行安全备份；丢失密钥将无法解密已保存 API Key。
2. 使用独立迁移身份审核并执行 `platform_0004_developer_console`；保留旧业务结构和数据。
   已存在的受限运行角色仅获得五张新表及序列的必要权限。新装环境另行执行专用角色授权。
3. 使用 `python -m server.developer_admin --username <已有管理者> --confirm medical_app_platform`，
   从本机隐藏提示输入已有管理者密码；管理连接仅从 `PLATFORM_MIGRATION_DATABASE_URL`
   读取。工具不会创建管理者、不会重设密码，也不会输出连接详情。`--revoke` 撤销开发者授权。
4. 配置独立加密文件、更新后端代码、检查 HTTPS/登录/权限/配置发布/次次启动激活/回退。
5. 原 v3 `platform_admin`、备份、部署归属校验对表集合和策略指纹采用严格白名单；
   它们不能被当作已验证 v4 运维工具继续使用。生产升级前必须同步扩展相应的表集合、
   策略、序列和目录指纹验收，或使用经过独立校验的 PostgreSQL 全量备份工具。
   不得跳过原检查、伪造旧结构摘要或用 v3 验证结果宣称 v4 已上线。
6. 自动降级被禁止，避免删除已发布配置和待生效数据；需要回退时保留新增表及备份，
   回到兼容客户端/后端代码，而不是自动丢弃新表。

## 验证

`tests/server/test_developer_console.py`：合成 SQLite HTTP 测试，覆盖独立授权、过期/撤销、
安全字段、加密不可回显、版本冲突、延迟生效、原记录冲突、密码重置及会话撤销。
`tests/server/test_developer_console_pg.py`：仅在明确启用
`MEDICAL_APP_RUN_TRANSFER_PG_TESTS=synthetic-local-only` 后运行，创建并清理有归属标记的
本机临时 PostgreSQL 17 容器，实际验证非管理员运行角色的 RLS 和 v4 事务流程；不接触云端。
