# 默认 AI 通道与桌面提醒：实现及部署边界

本文描述代码接口和安全门槛，不代表生产密钥已配置、云端已发布或真实 AI 验收已完成。测试应使用合成账户和模拟 DeepSeek；真实付费调用必须由负责人另行明确确认。

## 同一套 AI 设置

桌面 `ChatPage` 和今日语音智能填写复用同一个 `_selected_provider()` 回调，每次操作时即时解析；语音转文字本身仍是本机离线识别，不是将录音上传给 DeepSeek。

- 个人显式设置的 DeepSeek Key 优先，经当前 Windows 用户 DPAPI 加密、按数据来源及稳定账户身份保存；使用时由设备直连固定的 DeepSeek 官方接口，不提交给本平台。
- 云端登录且无个人 Key 时，设备只携带自己的短期登录令牌调用本平台默认 AI 代理。新设备不需要拿到共享 Key。
- 本地登录且无个人 Key 时，继续使用该 Windows 用户已经单独配置的 DPAPI 默认 Key；发布包不包含 Key。
- 无可用默认通道时明确显示不可用，不伪装成模型已作答，也不悄悄切换另一个付费主体。
- 医疗记录仅归纳用户明确叙述的就医、既有服药经过；不推断诊断、推荐自行停换药或调整剂量。环境记录不是实时天气监测。本版不增加外部地理或天气查询。
- 普通生活问题读取数据库上下文前仍需要当前账号的分享选择；上下文仅限本人或已有服务权限允许的范围。语音表单提取只发送该段文字及提取提示，不自动附带历史健康资料；表单必须经用户确认才保存。

## 服务端密钥文件契约

推荐容器内路径与环境变量如下，两个文件应分别只读挂载、分别保管：

| 环境变量 | 推荐绝对路径 | 内容 |
|---|---|---|
| `HEALTHLIFE_AI_SECRET_ENVELOPE` | `/run/ai-secrets/deepseek-key.aesgcm` | AES-GCM 密文 |
| `HEALTHLIFE_AI_SECRET_KEY_FILE` | `/run/ai-key/default-ai-kek.bin` | 独立随机 32 字节二进制解密密钥 |

密文二进制布局：

```text
ASCII "HEALTHLIFE-DEFAULT-AI-1\n"
├── 12 bytes：随机 nonce，每次加密必须重新生成
└── ciphertext + 16-byte authentication tag：AES-256-GCM 输出
```

加密原文是 DeepSeek Key 的 UTF-8 字节，不含换行；附加认证数据固定为 ASCII `HealthLife/server-default-ai/v1`。格式由 `ENVELOPE_MAGIC` 与 `ENVELOPE_AAD` 常量定义。解密依赖固定版本的 `cryptography`，必须进入服务端经过真实下载校验的依赖锁；不要编造 wheel 哈希。

文件必须是不同的绝对路径，且不能包含符号链接、重解析点或硬链接。Linux 文件所有者应为 root 或实际服务 UID；建议 `0400`，专用服务组确有需要时可用 `0440`，禁止组写及其他用户任何访问。父目录和宿主机 secret 目录还应由部署方设为不可被其他用户写入；文件名及环境变量里不能包含 Key 正文。

只在服务器内存中解密，不生成明文后备文件，不把 Key 放入源码、Dockerfile、镜像层、客户端、日志或健康数据库。AES 密文与解密密钥若被一同取得，攻击者仍能解密，因此“加密落盘”不替代分离保管和严格权限。进程需要在内存中使用明文 Key；不能宣称运行中内存不存在 Key。

两个环境变量都未配置或读取／认证解密失败时，默认 AI 接口安全返回不可用；不会打印文件内容、原始驱动错误或请求内容。不要通过请求参数、任意 URL 或环境代理覆盖 DeepSeek 上游。

## 认证、限额和流式协议

固定路由：

- `POST /v1/ai/chat`：完整 JSON 回答；输入仅允许 `model`、`messages`、`max_tokens`。
- `POST /v1/ai/chat/stream`：SSE 流式回答；事件为 `{"delta":"..."}`、最终 `{"done":true,"model":"..."}`，或固定错误代码。缺少完成事件的回答不视为完整结果。

两条路由都需要本平台有效 Bearer 会话。账户、会话与顾问到期规则由既有认证服务核验，身份不能由请求中的用户编号指定。上游固定为 `https://api.deepseek.com/chat/completions`，禁止重定向和继承 HTTP 代理环境；只允许文字模型 `deepseek-v4-flash`、图片实验模型 `deepseek-v4-flash-vision-exp`。客户端不能提交服务 Key、目标 URL、工具调用或任意模型。图片只接受受限的内嵌 PNG/JPEG，不接受远程图片 URL。

默认限制：请求体 4 MiB、32 条消息、文字合计 32,000 字符、最多 2 张图片、每张最多 2 MiB 且边长不超过 2048、最多 2048 输出 token；上游总等待最多 90 秒。流式模型身份、结束原因和完成标记均需验证，不向客户端透传推理字段或原始上游错误。流式内容每个不超过 1024 字节的读取批次均重新核验当前会话，已过期或撤权时不继续交付后续批次；已经合法送出的文字无法撤回。

| 范围 | 默认安全上限 | 可调低的服务器环境变量 |
|---|---:|---|
| 每用户每分钟 | 2 次 | `HEALTHLIFE_AI_USER_MINUTE_LIMIT` |
| 每用户每 UTC 日 | 20 次 | `HEALTHLIFE_AI_USER_DAY_LIMIT` |
| 每平台数据库每分钟 | 6 次 | `HEALTHLIFE_AI_GLOBAL_MINUTE_LIMIT` |
| 每平台数据库每 UTC 日 | 100 次 | `HEALTHLIFE_AI_GLOBAL_DAY_LIMIT` |

环境配置必须为正整数，不能高于表中上限，没有无限模式。所有调用先在数据库短事务中原子预留额度，然后才发送上游请求；上游失败仍占用该次额度，应用不自动重试。额度已满的请求不再消耗其他用户的全局份额。固定窗口在边界附近可能出现相邻两个窗口的请求集中。

**“全局”是同一个平台数据库，不是整个 DeepSeek 付费账户。** 当前发布只保留 Aliyun 单一运行路线，默认 100 次/日即该平台上限。未来如果另增独立后端，必须重新分配总预算或使用统一协调服务；本版不会假装独立数据库已经共享记账。平台计数也不包括用户使用个人 Key 的直接调用。

无需新增表或放宽数据库 CHECK：登录限流占用 `auth_rate_buckets` 的 `0..8190`；AI 全局日/分钟为 `8191/8192`，用户分钟为 `8193..12288`，用户日为 `12289..16384`。不同周期不共享桶，身份 HMAC 碰撞只会更保守限流。登录清理只处理自己的域，AI 记账不会删除登录桶；旧登录桶可能造成短期保守限流，不会扩大额度。生产以 PostgreSQL 时钟和事务锁协调多进程，不能以进程内计数替代。

部署切换必须先停止全部旧版 API 实例，再启动新版并启用默认 AI。旧版认证清理器没有上述域隔离，禁止让旧版和新版服务混跑同一个数据库；历史旧桶可以保留，但旧清理进程不可保留。新版多个进程由同一个数据库协调。

## 主窗口集成与提醒边界

```text
MainWindow（主窗口）
├── ChatPage(cloud_client=同一个认证客户端)
│   └── 今日智能填写调用同一个 _selected_provider 回调
└── ReminderScheduler(health_service, preferences_service, namespace=明确的数据来源)
    ├── 登录成功：start(user)
    ├── 提醒编辑／暂停／删除成功：refresh()
    ├── 登出／身份变化／授权失效：stop()
    └── reminder_due(dict)：主线程展示柔和、非模态提示
```

提醒事件含 `user_id`、`reminder_id`、`title`、`preferred_name`、`message`、`scheduled_at`、`timezone`。数据读取和加密磁盘操作在工作线程执行；旧会话返回的数据通过世代校验丢弃，身份不匹配或权限读取失败时不使用旧资料提醒。`refresh()` 会使旧在途读取失效。

支持数据库既有 `none/daily/weekly/monthly`。重复按个人当前时区下首发时刻对应的当地钟点计算；个人时区变化也会改变首发时刻的当地表示。每月没有对应日期时跳过该月；夏令时不存在的当地钟点跳过，重复小时只触发第一次。一次提醒以及重复提醒都仅补报最近五分钟内的到点事项，不在重启或长时间休眠后集中补报历史积压。

本机 DPAPI 去重标记按来源和账号隔离，使用本机锁协调多开实例，先写交付标记再展示，防止重启和并发窗口重复提醒。该顺序存在一个诚实边界：如果写标记后、展示前进程崩溃，可能漏掉那一条提醒；这不是医疗级通知保证。缓存不可安全读取时不使用明文后备。

提醒只在应用与登录会话运行期间有效；退出程序、关机或系统未运行时不能提醒。本版不是后台 Windows 服务，不创建系统级定时任务，也不提供服药决策或紧急医疗报警。

## 发布前验证门槛

- 模拟 DeepSeek 验证真实 API 路由：缺失/撤销会话、固定目标、模型限制、画像/上下文隐私、错误脱敏、无自动重试、流式断开及结束标记。
- 共享配额：登录桶与 AI 桶不重叠、旧桶兼容、每用户和全局分钟/每日限制、多个账户及独立连接并发、UTC 跨日与时钟回退。
- 真实本机一次性 PostgreSQL：最低权限 runtime 角色、原有 CHECK 与强制 RLS 完整、两个独立连接引擎的并发额度原子性；只清理由测试创建且已核对标签的容器资源。
- 提醒：时区、重复、DST、暂停/删除、身份变化、跨重启与多开去重；UI 必须在登出和授权失效时关闭提醒显示。
- 两端 RPC 白名单都允许 `chat.delete_conversations`，服务必须先验证全部对话归属再在一个事务内删除；正在生成的会话拒绝删除。删除全部后仅补建一个本人空会话。
- 全套桌面及服务端回归完成、依赖锁与发布包检查完成后，才由负责人决定是否进行一次最小、显式授权的真实付费 AI 验收。本文不替代该验收记录。
