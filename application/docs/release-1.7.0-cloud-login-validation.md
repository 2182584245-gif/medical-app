# 1.7.0 电脑版登录修复与阿里云上线验收（2026-09-19）

本记录补充此前 r2 的历史本地验收，不覆盖或改写当时“尚未部署生产”的事实。
本次由服务器所有者授权临时 SSH 部署、升级现有云端和导入虚构体验资料；不制作安卓包。

## 修复原因与范围

- 云服务器原先运行 v3 API，缺少 `/v1/developer/login` 等开发者接口，导致桌面显示找不到数据。
- 已将实际阿里云 API 切换为 v4，新增五张开发者私有表；原有 32 张表、账号与密码保留。
- 仅为经原密码验证的现有所有者授予开发者权限；普通运营账号和会员、顾问不能获得该权限。
- 修复客户端启动鉴权失败后继续进入主界面的路径；明确区分旧后端缺接口和密码错误。
- 用户尚未保存连接模式时，不允许开发者入口悄悄使用前一个后端。
- 扩充资料验收发现 PostgreSQL 384 MiB 容器上限触发 OOM，内核与数据库日志相互印证。
  在现有 4 GB 主机将数据库容器上限在线调整至 1 GiB，并保存到 Compose；未增加付费资源、
  未重启数据库、未更换数据卷。单纯加大上限后，连续访问仍曾触发 OOM，因此最终同时关闭
  此短事务服务不需要的 PostgreSQL JIT，热加载配置并仅重启 API 回收旧连接池。
  之后两位会员并发各两轮完整分页读取通过，连续 20 次健康检查全部成功，单次最长 0.285 秒，
  复核内核日志未出现新的 PostgreSQL OOM。未修改权限、RLS 或账号密码。
