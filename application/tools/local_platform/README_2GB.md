# 2 核 / 2GB 测试预算的本地演练

本工具测试现有 Python 后端 + 真实 PostgreSQL，不是购买或部署阿里云服务器。
它不会改正式云端连接、真实账号、用户历史数据、桌面程序或原本的实验数据卷。

## 限制怎么设置

| 组件 | 内存硬上限 | CPU 配额 | CPU 绑定 | 交换内存 |
| --- | --- | --- | --- | --- |
| API 后端（单进程，原密码哈希强度不变） | 1024 MiB | 1.5 核 | 0–1 | 禁用 |
| PostgreSQL（原连接池及配置不变） | 512 MiB | 0.5 核 | 0–1 | 禁用 |
| 合计常驻服务 | **1536 MiB** | **2 核** | 同两个逻辑 CPU | 禁用 |
| 外部客户端模拟器 | 256 MiB | 1 核 | 2 | 禁用 |

MiB 为二进制内存单位，1024 MiB = 1 GiB。以 2 GiB 为服务器规划预算，余下 512 MiB
是给系统、容器引擎和将来的入口服务预留的空间，**不是已经测出的系统占用**。
Docker Desktop 虚拟机及 Windows 的总内存不调整；不影响其他容器。
这个测试严格限制了两项业务服务，但不是一台完整 2 GiB Ubuntu 虚拟机测试。
镜像构建、宿主采样程序及模拟外部设备的客户端不计入常驻服务器预算。
Docker CPU 配额也不能复制阿里云经济型共享 CPU 的具体性能。

## 运行

需要本机 Docker Desktop 的 Linux x86_64 引擎、至少 3 个可用逻辑 CPU，以及 Python
3.12/3.13。该宿主脚本只有 Python 标准库依赖。服务镜像继续使用已有锁定依赖，
精确白名单排除密钥、用户数据库、桌面模型；首次构建可能需要联网下载官方依赖。

在仓库的 `application` 目录执行：

```powershell
python .\tools\local_platform\run_2gb_test.py
```

该命令每次建立一个随机后缀的 `medical-app-2gb-test-...` 项目与 5 个专用卷，不使用
原来的 `medical-app-local-lab` 数据。全程只访问内部网络的 `https://api:8443`，
不开放 Windows、局域网或公网端口，不读取本机云端配置，不调用任何 AI API。

## 检查内容

1. 从 Docker inspect 与 Linux cgroup（容器实际资源计量接口）双重核对限额生效，
   确認禁用交换内存，防止从宿主大内存或 swap“借用”突破容器预算。
2. 复用既有 16 项首次验收：随机测试账号、登录、双客户端数据读回、多对话、
   合成聊天图片、文件上传下载、健康记录、北京时间、权限隔离、退出登录等。
3. 另外运行 1、3、5 个客户端的真实并发读写，每档 60 秒（不含登录准备和注销），
   保存请求量、错误、延迟统计。启用明确的限流观察模式：遇到 HTTP 429 仍计入失败，
   等待 0.5 秒后开始新的业务轮次（不是重放同一写请求），只要没有其他类型错误，
   就继续观察后续并发档位。这样不会因为一个客户端提前退出而把后半阶段冒充满员并发。
   回答是固定合成文本，**没有测试 DeepSeek/Ollama 的实际生成**。
4. 约每 2 秒采样；记录包含缓存的当前内存和内核峰值、CPU 用量与限流计数、
   内存不足事件。记录运行起始时间和重启次数，防止自动重启掩盖崩溃。
5. 停止并重新启动本轮 API 和数据库，复用 9 项持久性验证，读取原合成记录。
6. 测试结束只停止本轮项目，包括可能遗留的测试客户端，保留所有测试卷；
   不停止或删除其他项目，不重置数据库、不降低密码哈希强度。

结构化结果位于 `application/outputs/capacity-2gb/<本次时间与编号>/result.json`。
失败结果同样保留，不能用旧报告代替本次失败。程序退出码 0 表示本轮全部检查通过，
1 表示未通过。出现限流也不能标记为零错误通过，但程序仍会完成资源核验和重启读回，
报告以 `test_workflow_completed` 区分“测试执行完成”和“所有验收门槛通过”。
通过不等于正式上线验收、长期容量保证或整机压力测试。

## 本轮不覆盖

- 阿里云实际 CPU、磁盘 I/O、公网带宽、域名、备案与正式 HTTPS。
- Ubuntu、Docker 引擎及 Caddy 在完整 2 GiB 整机上的合计开销。
- 桌面 UI、安卓 UI、真实 AI、OCR、语音模型、长时间压力、大规模历史或大文件。
- 镜像构建峰值、数据库整库备份恢复、跨设备迁移与灾难恢复。

测试卷存放在 Docker 管理目录，复制仓库不会复制这些卷。反复运行会增加本机磁盘
占用；如需清理必须按报告中的精确项目/卷名另外确认，程序不会自动删数据。

限额机制依据 [Docker 官方资源限制文档](https://docs.docker.com/engine/containers/resource_constraints/)。
数据库连接池及连接上限参考 PostgreSQL 最佳实践技能检查，未改动业务 schema 或权限。
