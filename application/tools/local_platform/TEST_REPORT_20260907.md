# 本地容器部署验收记录（2026-09-07）

## 范围与结论

已构建现有 Python 后端的独立本地实验环境，真实 PostgreSQL 数据库初始化、
容器内 HTTPS 接口与停止后重启的历史记录验证通过。这不是腾讯云正式上线，
不代表桌面安装包已连接该实验环境，也不是全部产品功能的端到端验收。

本轮未连接正式 Supabase / Railway / Render / 腾讯云，未导入本地历史数据库，
未调用 AI、未购买服务、未修改系统受信任证书或 Windows 安装包。

- HTTPS 存活及就绪检查。
- 未登录请求与不受信任 Host（主机名）拒绝。
- 注册时注入管理员角色被拒绝。
- 创建两个随机合成普通账号。
- 三个独立客户端登录，其中两个使用同一账号。
- 创建两个会话，验证重复请求不会重复创建、冲突请求被拒绝。
- 带图片的聊天记录保存，回答为固定合成文本，**没有调用 DeepSeek 或其他 AI**。
- 文件上传。
- 创建北京时间生活记录及提醒。
- 同账号另一客户端读取相同会话、消息、图片附件。
- 下载文件并核对 SHA256。
- 不同账号之间的越权访问被拒绝。
- 北京时间日期、UTC 保存值与提醒时间往返一致。
- 退出登录仅撤销当前会话，不影响另一客户端。
- 其余测试会话退出后，旧令牌不可继续使用。
- 测试状态以独立卷、0600 权限保存，不输出密码或令牌。

重启验收重新登录相同合成账号，读回相同的 2 个会话、2 条消息、1 个聊天图片、
1 个文件、1 条生活记录及 1 条提醒；不新建业务数据。

TLS 测试分别确认：正确 CA 和主机名握手成功；没有可信 CA 时明确拒绝；
主机名错误时明确拒绝。网络超时或连接失败不会被当作证书拒绝成功。

## 本轮发现并处理的问题

- PostgreSQL `inet_server_addr()::text` 会带 `/32` 前缀长度；改为
  `pg_catalog.host(inet_server_addr())` 提取主机地址，保留原私网、身份、TLS 检查。
- Compose 在指定 Docker Desktop 集成构建器时出现选择兼容问题；改用经过本地
  端点校验的 Buildx 构建，再由 Compose `up --no-build` 启动，不改变全局构建器。
- 精确构建白名单遗漏了 `server/schema.py` 这一命名空间常量模块；补充该唯一文件，
  增加白名单回归和镜像构建时的导入检查，没有扩大到整个源码目录。
- 本机 Docker 29.7.2 的纯内部网络中，配置的宿主端口没有真正生效：
  运行态端口映射为空，Windows TCP 18443 检查失败。因此已**删除无效端口配置**，
  不再宣称 `localhost:18443` 可访问。相关现象也见
  [Moby 仓库用户报告](https://github.com/moby/moby/discussions/53256)，
  该报告不是对所有 Docker 版本的行为保证。

## 最终访问边界与数据保存

- 本轮入口为 Docker 内部的 `https://api:8443`，只通过配套验收脚本访问。
- API 与数据库均不向 Windows、局域网或公网发布端口；仅连接内部 Docker 网络。
- API 非 root、程序文件只读、无额外 Linux capabilities，不能挂载数据库管理员
  口令或测试 CA 私钥；密钥与测试历史不在构建上下文中。
- 5 个专用卷保存数据库、CA、数据库凭据、API 凭据和合成验收状态。
- `Stop` 不删卷。**复制仓库文件夹不会迁移 Docker 数据卷**；本轮没有实现
  Docker 卷导出/恢复工具，现有桌面便携版的保存位置没有改变。
- 真实用户的账号、健康资料、文件、管理员密码、AI Key 均未加入实验数据库。

`docker-desktop` 仍为 Stopped、引擎管道仍未恢复，没有重装或重置。
因此不能声称服务交付时仍在线，也未取得最终无宿主端口配置下的又一次历史读回结果。
上面的 16 项接口与 9 项停止/启动读回结果来自此前真实成功运行，不是离线模拟。

下次使用前请手动打开 Docker Desktop，等待引擎启动，再执行 `Start` 和
`VerifyPersistence`。如果 Docker Desktop 本身仍无法启动，应先检查其界面错误；
不要因而删除数据卷、关闭证书验证或关闭安全软件。
