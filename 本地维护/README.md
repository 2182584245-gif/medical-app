# 本地维护资料

本目录将最新版部署资料和回退备份集中保存在本地仓库文件夹内，但不把这些原始资料加入 Git 版本管理。

```text
本地维护
├── 部署资料
│   └── medical-app-deploy-20260919-v170
├── 回退备份
│   ├── medical-app-private-backup-20260919-loginfix-224644
│   └── medical-app-release-20260919-v170
└── 归档记录
```

## 用途

- 部署资料：1.7.0 后端部署包、镜像、维护脚本和当时的验收记录。
- 登录修复备份：修复登录前的私人数据库、本地云镜像及运行文件。
- 版本回退备份：此前保留的私人运行副本、私人数据库和升级前源码压缩包。
- 归档记录：迁移前后的文件校验、旧路径到新路径的映射，以及本次必要的脚本路径调整记录。

## 隐私和使用边界

除本说明和 `.gitignore` 外，这里的文件均由 Git 忽略。不要使用 `git add -f` 强制提交，也不要把整个目录公开上传。`.gitignore` 不是加密措施，也不能替代其他磁盘上的备份。

本次归档不会执行维护脚本，不会登录服务器，不会部署、恢复或迁移云端数据库。这里保存的验收报告只代表当时的检查结果。

旧日志、JSON 验收记录及备份内部的历史路径保留原样。维护脚本即使已调整本地位置，也不代表可以直接重新部署：历史版本、镜像、凭据、访问授权及服务器状态仍须在实际维护前重新核对。

本次对部署目录内的 `accept_live.py`、`accept_two_members.py`、`verify_export_images.py` 和 `run_remote.py` 做了本地路径适配，改为相对脚本/仓库位置定位；调整前原件另存于 `归档记录/调整前部署脚本`。没有修改云服务器路径或关闭 SSH 主机验证，也没有执行这些脚本。

应用内的 `application/tools/sync_repository_source.ps1` 另有既存的旧桌面路径配置；它不依赖本次搬迁的三个目录，本次未修改或执行。若以后需要使用该旧源码同步工具，应单独检查来源和目标，避免在同一份仓库内自覆盖。

`测试/整理记录` 中较早的清理清单记载的是迁移前位置，仅作为历史凭据，不是当前目录索引。当前实际位置以本目录和本次归档记录为准。
